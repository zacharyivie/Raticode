# Raticode Mobile

> **User documentation is on the website:** [Raticode Mobile](../../website/docs/mobile/index.md). The website is the single source of truth for how the app works; a phone change users would notice updates it before merging. This README keeps build, test and release instructions, and the per-version notes below record each feature's design and verification status for developers. Developer notes are indexed in [docs/README.md](docs/README.md).

If pairing waits at authentication, check desktop's device-network opt-in and firewall before reinstalling. Normal `electron:dev` startup does not enable phone connections. A listening device port still needs a firewall rule allowing the phone. See [connection setup and recovery](docs/live-device-setup.md#update-without-resetting-pairing) and [Linux firewall checks](docs/live-device-setup.md#linux-firewall-checks).

Android companion for Raticode Desktop. The app opens directly into live pairing or authorized conversations with Rem. The local demo is no longer included in the APK. Historical simulator helpers live only in test source sets; upgrading does not delete their old encrypted data or existing live pairing, drafts, files and queued messages.

Live messaging requires Android 10 or newer. Desktop confirmation and project/thread grants remain authoritative. The phone talks to your desktop over Wi-Fi, using pinned end-to-end TLS 1.3. Away from home it can use your own Tailscale network if you turn that on; otherwise it never uses mobile data, a VPN or an internet relay. No Raticode SaaS backend exists. All Rem work runs in Raticode on your computer; the phone only sends requests and shows results.

## Conversations and connections

- Pair using **Scan desktop QR** or **Paste invitation**, then confirm the phone on desktop. Invitation review shows the desktop's Wi-Fi address; invitations without one are rejected. Pending pairing and Desktop both offer **Set desktop address** for a changed or blocked address.
- **Sync desktop threads with this phone** is enabled by default when you confirm a new phone in desktop **Paired devices**. Existing and future desktop threads, text history and the provider/model catalog sync through the encrypted connection. Raticode can run in the background; closing its window keeps sync going from the tray. Your phone uses your desktop projects and approval policies.
- **Threads** uses the desktop's sections and rules: **Pinned**, **Unread** (blue dot, bold title), **Read** (your seven most recently read threads), **Running** and **Archived**. Running and Archived are collapsed until you tap them, as on desktop. Each row shows its date and project or Global. Unread comes from the desktop. Opening a thread, **Mark as read**, **Mark all read** on the Unread header, and archiving all mark threads read. With **Use Raticode from this phone** on and a desktop that supports it, those reads and **Mark as unread** reach the desktop too; otherwise they change the phone only. Long-press a thread to select it; while selecting, taps add or remove threads, tapping a section's name (such as Unread) selects every thread in it, and the bar at the top marks them read or unread, pins, archives, restores or deletes them. Back or the close button ends selecting. The scope dropdown filters projects; the toolbar opens search and Desktop settings. Rows archive, or delete when archived, and their menu selects, marks read or unread, pins, unpins, restores or deletes.
- Open a conversation and send a message. **Queued on phone** changes to **Accepted by desktop** only after a durable authenticated receipt. Rem's reply appears in the same conversation. Drafts and history stay with their thread.
- The app connects to its saved desktop when opened, binding its socket to the phone's Wi-Fi network. Without Wi-Fi it waits and reconnects as soon as Wi-Fi returns, unless **Connect through Tailscale** is on. Desktop supplies its updated address through encrypted sync.
- Wi-Fi packet reads retain partial headers and bodies across short Wi-Fi pauses, with a 30-second frame deadline. The thread-list composer enables creation when an eligible desktop grant arrives and keeps unsent drafts while offline.
- Desktop selects its default private interface address when device networking is enabled. `RATICODE_DEVICE_HOST` overrides that choice. Router client isolation, guest Wi-Fi or a firewall can make the desktop unreachable. There is no fallback route; fix reachability or use **Set desktop address**.
- **Wake computer** appears on **Desktop**, and on other pages once a connection attempt has failed, if you turned on the matching setting in desktop Paired devices and this phone is on the desktop's Wi-Fi subnet. One tap sends one Wake-on-LAN packet over Wi-Fi and the app reconnects as usual. The button says only that the signal was sent, because nothing confirms it worked. It doesn't work over Tailscale, and your computer's firmware must allow Wake-on-LAN. The packet is unencrypted by design and holds only the network card's hardware address. This needs the matching desktop update; until then the button stays hidden.
- Chat stays on the thread list until you open a conversation. **Threads** shows the desktop's Pinned, Unread, Read, Running and Archived sections. **Search in threads** searches saved desktop messages and opens the matching message. Send from the list to create a shared thread, or use the small **New thread** icon. No name is required. Desktop names it from the first message's first eight words. Select Global/project, provider, model, effort and permissions before sending; the same controls remain available in chat. These changes retain the thread's identity and history. **Attach file** adds up to eight verified uploads, each shown as a thumbnail or file-type tile that previews when tapped, and **Dictate** uses Android on-device speech recognition. **Stop Rem** requests cancellation. Chat keeps the composer below a scrolling message list. **Desktop** contains connection controls, file transfer, history cleanup and generic response notifications. **Enable background sync** starts the visible Android service; otherwise leaving the app disconnects and opening it reconnects.

- Once paired, the app opens to the first destination on the bottom bar. By default the bar holds **Rem**, **Threads**, **Orgs**, **Swarms** and **More**, from left to right. **More › Bottom bar** lets you choose up to four destinations and their order from Rem, Threads, Organizations, Swarms, Source control, Files, Workflows, Approvals, Usage, Voice assistant, Desktop settings, Developer log and Browser; **More** stays last and lists everything left off the bar. Back from another bar destination returns to the first one, a page opened from More goes back to More, and back from an open thread returns to Threads. Notifications, the share sheet and voice mode still open the thread, approvals or Rem chat they point to. With **Use Raticode from this phone** turned on in desktop Paired devices, you can talk to Rem and manage its tasks, work with organizations (overview, projects, the issue board, workers and knowledge), start swarms, change desktop display and Rem default settings, check provider usage, and follow the desktop's Developer log. Long-press log entries to copy them or to attach them to Rem's message box with **Ask Rem**, which never sends by itself. You can also browse the projects open on your computer and open their files (see below). Everything runs on your computer under its approval policies. Editing files, files that may hold passwords or keys, terminals, the browser, credentials and agent permissions stay on the desktop.
- **Rem** looks like the desktop's Rem chat: the rat face beside Rem's replies, your messages in lavender bubbles, day labels and task cards. Each message shows when it was sent (the time today, the day and time on older messages), and back-to-back Rem replies are split by a faint line. The paperclip opens a menu of where to attach from: **Photos and videos** (Android's photo picker), **Camera** (the photo goes straight into the message and isn't saved to your gallery), and, under **In Android's file browser**, **Recent files**, **Downloads** and **All files** (phone storage, SD card, Drive and other apps). Those three open Android's own file browser at that place, where you pick the file; if it opens somewhere else, choose the place from its ☰ menu. You can pick several files at once, up to eight per message and 10 MB each, and remove any one before sending. Each attachment shows as a small thumbnail (a picture or a video's first frame) or a colored tile with its file type, in the message box and on the sent message; tap it to see the picture full screen, play the video, read a text or code file, or open anything else in another app. Files attached on your computer show here too, and files the phone sent come back from the computer once the phone's own copy is gone: pictures and videos load by themselves, other files when tapped. A file deleted on the computer, or a phone that isn't connected, is shown as such. The camera asks for permission the first time; if you refuse, the message box says so and offers Settings. Ask Rem to send you a file, such as a saved report, and it appears under the reply. Tap its name to download it and open it in one step; **Download**, **Save** and **Open** stay beside it. Pictures and videos Rem sends download by themselves and show right in the chat: tap a picture to see it full screen (pinch or double-tap to zoom), or a video to play it in Raticode. Save and Open stay under each one. Open hands a temporary copy to an app you choose, such as a PDF or photo viewer; if no app can open it, Raticode says so and offers Save. App packages (.apk) must be saved and installed from your Files app. Images in replies, like a photo Rem found, load through your desktop; the phone never contacts the image's site. The bottom bar uses the desktop's icons. Attachments, sent files and images need the matching desktop update; without it the phone shows a note or a tap-to-open image card.
- A task's work thread reads like the desktop's: Rem's instructions as bubbles, each run of the worker's steps folded under **Show thoughts**, and the report in full. A running thread opens at its newest step.
- **More › Global board** (or **Board**, if you pin it to the bottom bar) shows every organization's tickets and Rem's own by column. You can add a ticket for Rem or any organization, assign it to a worker, or hand one of Rem's tickets to an organization. **Proposed** is where Rem's ideas wait for your Approve or Decline; nothing there runs until you approve it. **People** lists Rem and every organization's agents like the members of a ticket tool; tap someone to choose the projects they may work in during self-work. **Self-work** turns it on or off, sets the maximum threads and whether Rem pulls work from Backlog once To do is empty, and shows the running report of tickets added and work done. Rem's chat shows **While you were away** when the report has something new. The desktop owns all of it and needs the matching update; with an older desktop the page asks you to update Raticode on your computer.
- Rem's tab opens to the chat. Tapping Rem's status at the top ("1 thing needs you") opens the **Tasks** list, and its back arrow or the system Back returns to the chat with the draft and scroll position kept. The list shows whatever ran most recently at the top, with running tasks first. A one-time task leaves the list once its run finishes and needs nothing from you; a failed one stays until you dismiss it. Its card in Rem's chat still opens the task and its work thread. Your desktop removes finished one-time tasks, their runs and work threads 30 days after the run finished; the chat message stays and its card then says the task was removed. An older desktop keeps every task, and the phone hides finished one-time tasks itself.
- Rem's chat looks and works like the desktop's. Finished tasks show a card with their checks, saved reports (Open fetches the report from your desktop) and the web pages the work used; page previews come through your desktop, so the phone never contacts those sites. Running tasks show Plan, Work, Check and Report steps with their checks and time so far. Replies can have an expandable **Details** section with tables, task lists, highlighted code with a Copy button and simple charts, plus up to three suggested replies that send as your reply when tapped; anything already typed in the message box stays there. While Rem replies, the header and chat say what it is doing, and with Claude Code the reply appears as it is written. Each message, Rem's or yours, has a ⋯ menu with **Reply**, Copy and, on Rem's replies, the model and time. Reply shows the message above the message box, with ✕ to drop it; the sent message shows it above your words, and tapping that scrolls back to it when it's among the messages on the phone. Rem reads the whole message you replied to, however far back it is, and a reply to a message that's no longer in the chat says so. Reply needs the matching desktop update. Long messages fold to a preview about a third of the screen tall with **Show more** under them, as on the desktop; Rem's newest message opens in full, and **Show less** folds a message again. New messages no longer pull you down while you read further up; a pill jumps to them. A message your desktop refuses stays with Try again and Edit. Under the newest update about a finished task, **Open report**, **Retry review** (when its review stopped) and **Run again** buttons use the same desktop actions as the task screen. An older desktop sends none of this, and the chat looks as before.
- Links in Rem's chat and in threads are underlined in the accent color. Full paths Rem writes to files on your computer link too, including paths with spaces and paths shown as code, once the desktop is updated to list them. Tap a web link to open it in Raticode's browser, or in your phone's default browser if you turn off **Open chat links here** in the browser's settings. Tap a link to a file on your desktop, such as a report path in Rem's reply, and the phone asks the desktop for that exact file without involving Rem; it downloads and opens in the app your phone uses for that kind of file, with no extra question in Raticode. Text such as Markdown opens in a plain-text viewer when nothing reads it directly. If no app can open the file, Raticode says so and offers **Save**. Only files in an open desktop project or the Second Brain folder can come to the phone, and only from links Rem or an agent wrote. File links need **Use Raticode from this phone** and the matching desktop update.

## Build and run

```bash
source ~/.config/android/env.sh  # This machine's installed SDK/JDK environment
./scripts/run-android.sh
./gradlew assembleDebug testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest
```

The launcher selects one connected device or starts `Raticode_Pixel_8_API_36`. Set `ANDROID_SERIAL` or `RATICODE_AVD` to choose another. SDK paths belong in environment variables or ignored `local.properties`. Use the committed Gradle wrapper. Gradle daemon criteria require JDK 21. Managed check commands must explicitly supply JAVA_HOME and Android SDK environment variables when the runner does not inherit the development environment. Keep host paths in managed run configuration or ignored local.properties. Release signing is optional and supplied only through environment variables. See [release preparation and acceptance](docs/release-readiness.md); an unsigned minified build is not a distributable release.

Validate the protocol fixtures without network or desktop execution:

```bash
python3 -m venv .venv-contract
.venv-contract/bin/pip install -r protocol/requirements.txt
.venv-contract/bin/python scripts/check-contract.py
```

The APK is `app/build/outputs/apk/debug/app-debug.apk`. Tests reset the test app's local workspace; export anything needed before running emulator tests against an installation you use manually.

### Versions and CI

The version is in `version.properties`; change it with `python3 scripts/version.py bump minor` (or `major`, `patch`, or an exact version). GitHub Actions (`.github/workflows/mobile-android-ci.yml` in the repository root) checks the version, script tests and protocol fixtures, then builds debug and unsigned release APKs with unit tests, lint and the release APK policy check. Emulator tests run only when started by hand. See [versions and release tags](docs/versioning.md).

Releases work like the desktop's. A push to `stage` builds, checks and tests a release APK (instrumented tests and a launch on an emulator, plus a dependency audit) and stages it as a draft GitHub release; a `mobile-v<version>` tag then publishes that exact signed APK. See [preparing a release](docs/releasing.md) for the steps and the one-time signing setup.

## Live v0 scope

- One paired home desktop, with thread sync enabled by default for new phone pairings. Shared scope, model, effort and permission changes sync in both directions. Codex, Claude Code, Cursor, Copilot, OpenCode, Antigravity and Grok use desktop adapters and policies without mobile-only permission caps.
- Encrypted durable outgoing messages, authenticated desktop receipts and generic opt-in response notifications. Enable notification alerts separately from background sync.
- Opt-in Rem chat notifications for Rem's replies and task updates on requests from this phone, shown as an Android conversation with a **Reply** button that requires an unlocked phone. Alerts are generic unless you also turn on **Show Rem's words**. They need a connection (app open or background sync on) and an updated desktop; there is no push service. See [Rem chat notifications](docs/mobile-desktop-v2.md#rem-chat-notifications-november-2-2026). Separate switches add alerts for a task needing you from any source, a task finishing and one **Proposals are waiting** alert per self-work round, plus quiet hours that silence alerts without losing them; these need a desktop that advertises support. See [Alerts for anything that needs you](docs/mobile-desktop-v2.md#alerts-for-anything-that-needs-you-november-9-2026).
- Explicit removal of completed local history and local file copies. Pending requests and lifetime replay-protection records are retained. Exported copies remain at the chosen destination.
- Desktop fleet snapshots with freshness and job identifiers. Fleet execution requires an explicit grant in desktop Settings plus target-local worker authorization. A phone never becomes a worker.
- Wi-Fi-only connections that reconnect when Wi-Fi returns. Existing identities and outbox IDs survive reconnects.

See the [release matrix and recommended decisions](docs/release-readiness.md) for signing, physical-device acceptance, Wi-Fi endurance and independent security review. Public release remains gated on those results.

See [security repairs and dependency scan scope](docs/mobile-security-fixes.md) for import cancellation, Back/keyboard behavior and build-tool patches.

Desktop **Phone > Unpair** removes pairing without revoking. **Revoked devices > Remove from revoked list** permits a fresh QR pairing without restoring prior access. Restart the desktop backend for these actions. See [pairing recovery](docs/live-device-setup.md#unpairing-and-revoked-identities).

Opening a Rem result with more than three source cards could pop up **Desktop request: The desktop already has a different request with this number. Send it again.** While the source previews loaded, the phone sometimes gave two requests the same number, and the desktop refused the second. ### Share to Rem

On Android 10 or newer, pick **Rem** in any app's share sheet to send a link, text, pictures, videos or PDFs to Rem's chat on your desktop. A sheet opens over the app you're in, showing the text (which you can edit) and each file with its size. Nothing goes until you tap **Send**. Then the files upload over the same end-to-end encrypted Wi-Fi connection and arrive with your note as one message. The sheet says **Sent** once your desktop has it, or **Queued** if it's still on the way. It refuses, and says why: other file types, more than 8 files, any file over 10 MB (or 40 MB together), files that weren't shared through Android's content system, and Raticode's own files. The sheet doesn't open over the lock screen, and Send refuses while the phone is locked. Shared text can carry instructions you didn't write, so check it before sending: desktop Rem treats everything you send as your request. This needs **Use Raticode from this phone** on the desktop; files also need a desktop with Rem chat attachments. No desktop update is required. Not yet tried on an emulator or phone; see the [design notes](docs/architecture.md#share-to-rem).

### Tidy voice messages

With **Tidy voice messages** turned on in desktop Settings, what you dictate in voice mode or with **Dictate** in a chat stays hidden until your desktop has tidied it with a fast model (punctuation, filler words, misheard names), then appears ready to edit. If tidying is off, unreachable or slow, your words appear as heard with a note. In voice mode the words so far are tidied and shown while it keeps listening: every 15 or more new words once 5 seconds have passed since the last round, and whenever you pause for two seconds. Each round re-tidies the whole message, so a sentence cut in half is mended next time. Send waits until something has been said and while a round is out (version 0.19.2). Swearing is written out as you said it on Android 13 and newer (version 0.19.1); older Android always masks it as "f***", and with tidying on the desktop writes such a word out only when there is one word it can be. More › Voice assistant says whether it is on. Needs the matching desktop update and **Use Raticode from this phone**. Checked with unit tests only; not yet tried on an emulator or a phone.

### Files on the phone

**Files** (in More, or on the bottom bar if you put it there) lists the projects open in Raticode on your computer. Tap one to browse it a folder at a time: folders come first, each row is a full-width tap target with the file's type, size and when it changed, a breadcrumb trail above the list jumps back to any folder, and the search button filters the folder by name. Back goes up a folder.

Tapping a file opens it full screen on the phone, the way the desktop app would open it. Code and other text show with line numbers and highlighting, with wrapping, find (with next and previous) and selection. Markdown, HTML and SVG show a preview with a button for the source. HTML runs no scripts and loads nothing from the internet. PDFs show page by page; pictures zoom with pinch or double tap, and animated GIFs move; video and sound play in the app. Office documents, archives and other formats offer **Open in another app** and **Save to phone**, which are also in every file's menu, with **Copy path**.

Large text files show their first 256 KB, and **Show all** downloads the rest when the file is 10 MB or smaller. Other files over 10 MB can't come to the phone, and their rows say so. A file opened before opens again offline while it is unchanged. Files that may hold passwords or keys, such as `.env`, are listed with a lock and never leave the computer, and links to other places aren't followed. It is read-only: create, rename, move and delete files on your computer. Android can't play `.ogv`, most `.avi` and `.aiff` files itself, so those offer another app. Needs **Use Raticode from this phone** and the matching desktop update. Tested on emulators at 320 dp and 411 dp wide against the real desktop code; not yet on a phone. See the [protocol section](docs/mobile-desktop-v2.md#file-explorer-november-6-2026).
### Ask Rem about a file or a change, 0.30.0

Version 0.30.0 adds **Ask Rem** to the places you read code. In **Files**, long-press text in a file and choose **Ask Rem** from the selection menu. In **Source control**, each file's change has **Ask Rem about this file**, each hunk has its own **Ask Rem**, and each commit has **Ask Rem about this commit**.

Each one opens Rem's chat with the project, the file's path inside it, the lines or the commit ID, and any text you picked already in the message box, up to 2,000 characters of it. Add your question and send it yourself: **nothing sends on its own**, and the words never pass through the phone's clipboard. Rem handles the message under the same desktop rules as anything you type, so asking it to fix something from here starts an ordinary request, and Ask Rem gives neither the phone nor Rem any new permission.

Line numbers appear when the phone can tell which lines you picked. A word that appears on several lines is settled by where you long-pressed it. Rendered Markdown shows only the words, because it has no line numbers of its own; switch to the source to include them. HTML and SVG previews have no Ask Rem. Files whose names look like they hold secrets, such as `.env` or a private key, offer no Ask Rem and their contents stay on the computer, as before. Needs no desktop update.

Hold a link or picture for more choices. Downloads ask first and go to Downloads; apps, installers and scripts get a second warning. Pages keep running while you use Raticode's other pages, so a music site in a tab goes on in Rem or Threads. ### Phone commands in voice mode

Version 0.21.0 handles phone commands in voice mode on the phone itself, with no desktop and no model, so they work offline and in about the time it takes to tap Send:

- **Calls and texts go straight through.** "Call Emily", "call mom at work", "call 555 123 4567", "text Emily I'm running late" or "send my brother a text saying dinner at 7" find the person among the people you saved on the phone (More › People Rem can reach) and show "Calling Emily" or "Texting Emily" with the message for 2–3 seconds. **Cancel** stops it, **Send now** / **Call now** skips the wait, and the pencil puts a text back in the box to change. Then the phone places the call or sends the text itself; the text shows in your messaging app like any other.
- **Texts are tidied on the phone.** "Um", "uh" and stumbles ("I I") go, spoken punctuation ("comma", "question mark", "new line", "period" at the end) becomes marks, sentences get capitals and an ending, and masked swear words come back ("f***" becomes "fuck"). Nothing is reworded and swearing stays.
- **Who it means:** one saved match goes ahead; two people saved as "brother", or one person's two numbers, ask which; a name nobody is saved as opens the contact picker and remembers the pick. **Ask Rem instead** sends the words to Rem when they weren't a command.
- **Permissions:** the first call or text asks Android for permission to place calls or send texts. Without it, the dialer or a draft opens instead. Emergency numbers are never called directly; the dialer opens for you. When Raticode is your digital assistant, Android grants the texting permission without asking (the assistant role includes it).
- **Everything else on the phone:** timers ("set a timer for 20 minutes"), alarms ("wake me up at 7"), "show my alarms", directions ("navigate to Home Depot"), places ("find coffee near me"), calendar drafts ("add dinner with Sam to my calendar tomorrow at 7 pm"), email drafts, opening an installed app by name ("open Spotify"), the flashlight, music ("pause the music", "next song", "resume the podcast"), volume ("turn the volume up", "mute the sound", "set volume to 40%"), and the time, date and battery level. A finished one shows **Ask Rem instead** for a few seconds.
- **Not a command:** anything with more to it ("call Emily and tell her the build is done", "call the API twice") goes to Rem as before, and so do bare words like "stop", "continue", "next" or "mute". Suggestions Rem writes under its reply always go to Rem as messages; they never call or text anyone. Voice mode also keeps words that start like a command off the desktop's tidy model while you talk.

Commands work in voice mode (spoken, or typed in its box). Typed messages in Rem's chat still go to Rem. Tested on an Android 16 emulator, where its simulated radio placed the call and sent the text; not yet on a physical phone.

### Background use, approvals, swarms and resources, 0.6.0

Threads keep working while Raticode runs only in the tray. Two limits that would have stopped a phone after days of background sync are fixed: the desktop's and phone's lifetime records of every polling request and snapshot. The phone's history is now a cache that frees space from other threads instead of stopping new replies. Rem's thoughts and tools refresh about once a second while a thread runs, and the backend reads the model catalog itself.

**Thread settings > Resources** turns the thread's desktop tools, skills and MCP servers on or off. With **Allow approvals and swarm controls from this phone** turned on in desktop Paired devices, **Thread list options > Approvals** answers workflow and swarm approvals and **Swarms** shows status, agents and the board, with pause, resume, stop and messages. The desktop carries out every action. Install this APK and restart the updated desktop backend and frontend together. See [setup](docs/live-device-setup.md#resources-approvals-and-swarms) and the [protocol extension](docs/mobile-desktop-v2.md#background-parity-extension-october-27-2026).
